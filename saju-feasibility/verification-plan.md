# 제품·개인정보·QA 명세

상태는 설계 단계다. 작업 디렉터리에 앱·서버·설정·데이터베이스가 없어 코드·구성 검토와 제품 QA는 실행할 수 없었다. 아래 판정표는 구현 후 더미 데이터와 모의 제공자로 검증한다.

## 1. 역법·입력 계약

- 대상은 한국 출생이다. 출생 날짜, 양력·음력, 음력일 때 윤달 여부, 시각 또는 시각 모름을 입력한다. 날짜는 달력 종류별로 실제 존재하는 날짜인지 서버에서 검증한다. 지원 연도와 한국 표준시 적용 범위는 기준 자료와 데이터에 맞춰 출시 전에 고정해 입력·결과 화면에 표시한다.
- 서버가 역법 변환과 간지 계산을 결정론적으로 수행하고 결과에 `calculationVersion`을 붙인다. 입춘과 월주 절입 판정에는 정확한 시각과 기준 시간대를 사용한다. 자시 일주 경계, 진태양시, 과거 시간대·서머타임은 사전에 지원 범위와 관례를 문서화하고 사례로 고정한다. 해외 출생과 지역 정밀 보정은 초기 범위에서 제외한다.
- 시각을 모르면 연·월·일 3주를 반환하고 시주 해석 제한을 표시한다. 출생일이 입춘이나 월주 절입일이어서 시각에 따라 3주 중 일부가 달라질 수 있으면 해당 항목을 미확정으로 표시한다. 결과가 확정된 항목만 해석에 사용하며 한 가지 시각을 임의로 대입하지 않는다.
- 양·음력 변환, 윤달, 절입 시각은 공식 역법·천문 자료와 대조하고 적용 연도와 자료 버전을 기록한다. 간지 경계나 자시 규칙은 채택한 명리 관례와 독립 계산 사례로 검증한다. 공식 자료의 가용 범위와 관례의 기준 사례는 미확인이다. [한국천문연구원 천문우주지식정보](https://astro.kasi.re.kr/)

## 2. 데이터·접근권한 설계

| 흐름 | 허용 데이터와 처리 | 보호·보관 기준 |
| --- | --- | --- |
| 입력 → 계산 | POST 본문에 생년월일·달력 종류·윤달·시각 모름 또는 시각. 범위 확정 전에는 세부 지역 수집 보류 | 비회원 원본 입력은 계산 요청 메모리에서만 사용하고 계산이 끝나면 폐기. URL·브라우저 영구 저장·서버 로그·분석 이벤트에 기록 금지 |
| 계산 → AI | `calculationVersion`, `pillars`의 확정 간지, `unknownTime`, `uncertainFields`, `topicId`, 출력 언어. 무료·유료 여부는 내부 템플릿 선택에 사용 | 서버에서 허용 목록으로 투영. 생년월일·출생 시각·지역·이름·이메일·사용자·주문 참조·자유 텍스트를 제외. 간지 등 파생정보의 보호 범위도 운영 심사에서 확인 |
| 주문 → 결제 | 서버가 내부 주문에 상품·가격·통화·상태를 기록하고, PG에는 결제 필수 필드만 전달 | 카드 정보는 PG 경로에서 처리. 리포트 저장소와 결제 기록 권한을 분리. 출생정보와 계산 결과는 PG에 보내지 않음 |
| 결제 → 리포트 | 재시도에 필요한 구조화 계산 결과와 주제, 리포트 본문, 결제 상태·참조, 소유권 참조 | 계산 입력 스냅샷은 생성·복구 기간에만 보관. 결제 완료와 소유권을 서버에서 확인하며 공유 캐시 차단 |
| 재조회 | 구매 전 전용 세션에 주문 귀속. 비회원 기기 변경 복구는 구매 때 발급한 임의 복구 코드로 설계 | 코드는 본문으로 입력하고 서버에 검증용 해시만 저장. 주문 식별자 단독 조회 차단, 입력 횟수 제한. 세션은 HttpOnly·Secure 쿠키, 유효기간과 폐기 지원 |
| 삭제 | 리포트·계산 스냅샷·복구 코드와 세션 접근을 폐기하고 생성 작업도 새로 발행하지 않음 | 법정 보존 대상 결제 기록은 필요한 필드만 분리 보관하고 목적·접근·만료를 별도 관리. 백업 복구 시 삭제 기록을 재적용한 뒤 노출 |
| 운영·분석 | 이벤트 유형, 채널, 무작위 코호트 키, 상품 구분, 성공·실패 종류 및 집계용 결제 이벤트 | 이벤트 스키마 허용 목록. 요청 본문, 응답 본문, 원본 입력, 보고서, 복구 코드, 결제 비밀값 기록 금지. 비밀키는 서버 전용으로 주입 |

비회원 재조회는 구매 세션과 복구 코드를 쓰는 설계 기본값이다. 보고서·계산 결과·세션·로그·백업의 보관일수 및 서버의 백업 소멸·복구 절차는 확정 전이다. 회의의 캐시 24시간, 로그·백업 30일은 검토 후보이며 원본 비회원 입력 무저장 규칙에는 적용하지 않는다. 상용화 전 국내 적용 법적 보존 범위, 미성년자 처리, 처리 고지, 국외 이전, AI 제공자의 학습 사용·보존·삭제·계약 조건을 확인한다. QA에서 실제 운영 설정과 계약 증적을 대조한다.

## 3. 결제·복구 계약

| 상태 이벤트 | 처리 | 사용자 화면과 통과 기준 |
| --- | --- | --- |
| 주문 생성 → 결제 확인 대기 | 서버가 확정한 가격·상품으로 결제 요청 | 4,900원·상품 범위·재조회·환불 조건을 결제 전 확인 가능 |
| 결제 확인 → 생성 대기 | PG 승인 및 주문·금액·통화·상태 대조. 웹훅 서명과 이벤트 ID 확인. 결제 상태와 생성 작업 예약을 원자적으로 기록 | 대기 상태에서 새로고침·결제 화면 복귀 후 구매 상태가 유지됨 |
| 생성 대기 → 생성 중 → 완료 | 주문당 활성 작업 1개. 출력 스키마·계산 일치 검사 후 제공 | 같은 결제로 재조회. 중복 알림과 워커 재시작에도 중복 생성·결제 방지 |
| 생성 중 → 일시 실패 → 재시도 | 자동 재시도 비용과 횟수 상한 적용. 복구될 때까지 결제 상태 유지 | 재결제 없이 상태·재조회 안내. 최종 실패면 환불 신청 경로 표시 |
| 환불 요청 → 환불 처리 중 → 환불 확정 | PG 정산 결과로 확정, 중복 요청은 동일 주문·환불 상태로 귀결. 생성 중이면 발행 차단 | 처리 중과 완료를 구별. 확정 후 유료 본문 접근 차단 및 코호트 집계 반영 |
| 삭제 완료 | 사용자에게 접근 폐기 및 삭제 처리 상태 안내 | 재조회·재생성 차단. 분리 보존되는 결제 기록의 목적과 범위 안내 |

잠정 설계는 무료 풀이 최대 1회, 유료 리포트 최초 1회와 자동 재시도 2회다. 각 호출 전에 입력 크기와 최대 출력 토큰을 검증하고, 주문별로 예약 원가와 누적 시도 원가를 기록한다. `누적 시도 원가 + 다음 호출 최대 원가`가 주문별 상한을 초과하면 재시도하지 않고 최종 실패 처리한다. 무료 방문자별 한도와 일일 전체 예산도 적용한다. 모델·토큰 단가·호출당 한도·유료 주문 및 일일 원가 상한은 공급자 견적과 실험 예산 확인 후 설정한다. 승인안의 200원은 기준 시나리오의 결제 건당 평균 원가 가정이다.

## 4. 회귀 테스트와 통과 기준

AI 출력은 `calculationVersion`, 해석 근거로 사용한 `referencedPillars`, `summary`, `sections`, `limitations`를 요구한다. 서버는 키·타입·길이, 사용한 간지가 입력의 확정값과 일치하는지, 불확정 항목을 확정 사실로 서술했는지 검증한다. 검증 실패 결과는 발행하지 않고 생성 실패로 처리한다. 평가표는 사례별 근거·허용 변이·금지 단정을 생성 전에 기록하며, 평가자가 사례별 5개 출력의 핵심 주장을 비교한다.

| 검증 | 준비와 기대 결과 | 상태 |
| --- | --- | --- |
| 역법 | 양력·음력 동일 날짜 쌍, 윤달/평달, 존재하지 않는 윤달, 윤년, 입춘·각 절입 직전·정각·직후, 날짜 경계, 표준시 지원 범위 첫날·끝날 및 범위 밖 입력. 공식 자료와 독립 관례 사례에서 기대 결과 전부 일치 | 설계·미실행 |
| 시각 모름 | 일반 날짜의 3주와 시주 제한, 절입일 불확정 항목, 오류 시 입력 보존과 수정 가능 여부를 API·모바일 화면에서 확인 | 설계·미실행 |
| AI | 확정 사례·시각 미상·절입 불확정·각 주제를 같은 계산값으로 5회씩 생성. 스키마 위반, 계산 속성 변경, 핵심 해석 모순, 의료·법률·투자·사고 관련 단정 표현 0건. 계산 일치는 자동 검사, 해석의 핵심 주장과 단정 표현은 합의된 평가표로 판정 | 설계·미실행 |
| 결제·복구 | 승인·가격·통화 검증, 웹훅 서명 검증, 중복 이벤트, 동시에 도착한 환불과 생성 완료, 잠깐 중단된 저장과 워커 재기동을 모의 입력으로 확인. 주문·작업·환불 중복 0건, 실패 시 구매 유지·재시도·환불 경로, PG 집계와 내부 집계 일치 | 설계·미실행 |
| 소유권·구성 | 소유자·다른 사용자·만료 세션과 미결제·결제·환불·삭제 상태의 조회/환불 조합 확인. 권한 없는 결과 제공 0건. 서버 전용 비밀 주입, 최소 권한, 환경별 키 분리와 배포 산출물 내 비밀값 미포함 점검 | 설계·미실행 |
| 개인정보 | 더미 출생정보와 복구 코드로 AI 모의 요청 스키마, URL·브라우저 영구 저장·로그·오류 추적·분석 노출 0건 확인. 만료·삭제 후 조회와 재생성 차단, 백업 복구 후 삭제 상태 재적용 확인. 보존·학습·국외 이전은 운영 계약과 설정으로 확인 | 설계·미실행 |
| 사용성·접근성 | 모바일에서 양력·음력·윤달·시각 모름, 잘못된 날짜 수정, 결과 이해, 가격·상품 범위 확인, 결제 후 재조회·삭제·문의 찾기를 무도움 조건으로 관찰. 키보드, 스크린리더, 초점 이동, 오류 안내와 색 대비 검증. 입력 완료율 75%와 결과 이해도 80%는 잠정 하한 | 설계·미실행 |

## 5. 실험 코호트와 판정

웹 유입 시 부여한 무작위 방문 키로 기간 내 중복을 제거하고 첫 유입 채널을 고정하는 방식을 초기 가정으로 삼는다. 다른 기기의 동일 방문자를 합치기 어렵다는 점을 기록한다. 내부 활동과 자동화 유입 제외 규칙, 집계 기간, 타임존, 결제 귀속 기간은 모집 전에 고정한다. 결제·환불은 서버의 상태 이벤트에서 집계한다.

| 지표 | 산식과 집계 기준 |
| --- | --- |
| 입력 완료율 | 입력을 시작한 고유 방문자 중 입력을 완료한 사람의 비율 |
| 결과 이해도 | 사전 정의한 이해도 과업 참여자 중 무료 풀이 범위와 시각 미상 제한을 올바르게 설명한 비율 |
| 첫 결제율 | 같은 코호트 순방문자 중 귀속 기간 내 첫 승인 결제 고객의 비율. 환불은 별도 사건으로 반영 |
| 유료 노출 후 전환율 | 유료 제안을 본 고유 방문자 중 첫 결제 고객의 비율. 결과 조회와 유료 노출도 별도 집계 |
| 환불률 | 적용 환불 관찰 기간이 끝난 첫 결제 건 중 환불 건 비율. 처리 중 건이 남으면 판정 보류 |
| 결제 고객당 획득비 | 같은 유입 코호트 채널 지출 ÷ 첫 결제 고객 수 |
| 순방문자당 기여이익 | 같은 코호트의 관찰 종료 후 결제·환불·정산, 생성·지원·유입 비용으로 산출한 변동 이익 ÷ 순방문자 수 |

2~4주와 첫 결제 100건은 계획 참고치다. 예를 들어 결제율 5%를 가정하면 100건을 기대하려면 순방문자 2,000명이 필요하다. Wilson 양측 95% 구간 예시에서 2,000명 중 100건 결제는 약 4.13~6.04%, 관찰을 마친 결제 100건 중 5건 환불은 약 2.15~11.18%다. 환불률 상한을 5%로 사전 합의하면 이 예시는 통과 근거가 되기 어렵다. 최소 표본은 결제율·환불률에서 허용하는 구간 폭, 목표 임계값과 유입 규모를 기준으로 산정하고, 환불 관찰 기간을 채운 마지막 코호트까지 확인한다.

역법·AI·결제·개인정보 QA와 사용성 하한을 충족하고, 실측 첫 결제율·환불률이 확정 기준을 만족하며, 양의 방문자당 기여이익과 손익분기 수준의 월 유입을 함께 뒷받침하면 출시를 제안한다. 표본, 환불 관찰과 사용성이 부족하면 보류한다. 손익 또는 유입 규모가 미달하면 가격·상품·채널 가설을 수정한다. 실험 시작 전 예산, 목표값, 표본, 관찰 기간, 판정에 쓸 불확실성 범위를 승인받는다.
